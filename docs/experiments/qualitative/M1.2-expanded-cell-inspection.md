### Shared ABALearn control flow (`gen`)

Both M12x arms run the same generalisation procedure in `gen.pl`. What differs between
ECAI and AAMAS is how each fold is computed and which non-intensional rule is selected
for folding; those differences are stated at the top of each batch. The shared skeleton
is as follows.

Learning begins from background knowledge together with a list of **non-intensional**
(rote) rules. Rote learning introduces one such rule per positive example, of the form
\(t(A) \leftarrow A=i\), and later may introduce further rote rules for contraries of
newly introduced assumptions. Only non-intensional rules are candidates for folding.
Background `val` predicates are folding *material*: they may appear in folded bodies,
but they are not themselves selected as rules to fold.

The outer driver is `genT`. It first attempts a complete derivation with the current
folding settings via `gen1`. Under non-deterministic folding only, if that attempt fails
entirely, `genT` increases the folding-token budget by one (up to `folding_steps`) and
retries. Under greedy folding that deepening branch does not apply. Procedural success
for `genT` means that `gen1` returned a finished framework; it does not by itself certify
that the written solution separates \(\langle E^+,E^-\rangle\) under the project’s
post-hoc ASP coverage check.

**`gen1`** selects one foldable non-intensional rule \(S\), computes a fold \(F\) of
\(S\), and passes \(F\) to `gen2`. If no foldable non-intensional rule remains, the
trace reports `gen1: nothing to fold` and `gen1` succeeds, returning the current ABA
framework as the learned solution.

**`gen2`** tests whether extending the current framework by \(F\) already entails
\(\langle E^+,E^-\rangle\). If it does, the fold is kept
(`extended ABA entails <E+,E-> - using folding`) and control returns to `gen1`. If it
does not, and assumption introduction is enabled, `gen2` attempts repair rather than
treating the failed entailment as an immediate global failure. Under the shared M12x
setting `asm_intro(relto)`, it first looks for an existing assumption relative to the
body of \(F\); if one is found, control passes to `gen3`. Otherwise it mints a new
assumption \(\alpha\), forms the patched rule with \(\alpha\) in the body, and continues
through `gen4` into `gen6`.

**`gen3`** handles reuse of an existing assumption under `relto`. If the framework with
the reused assumption entails \(\langle E^+,E^-\rangle\), the trace reports **OK** and
control returns to `gen1`. If not, it reports **KO** and that alternative fails, allowing
Prolog to backtrack into other folding choices for the same non-intensional rule where
available.

**`gen4` / `gen5`** only route after a new assumption has been generated. Both M12x arms
use `relto`, so `gen4` proceeds directly to `gen6`. The `sechk` path (`gen5`) is unused
in this experiment.

**`gen6`** rote-learns contrary atoms for the new assumption (typically rules of the form
\(c_\alpha(A) \leftarrow A=j\)) and appends them to the non-intensional list, so they
become later folding targets. Under **cautious** learning, `gen6` then re-checks
entailment and fails if the check does not hold. Under **brave** learning—which both
M12x arms use—that re-check is skipped, and control returns to `gen1` even if
\(\langle E^+,E^-\rangle\) is not yet entailed.

Two outcome distinctions used throughout the cell write-ups follow from this skeleton.

First, **engine termination** (`nothing to fold`, writing `bk.sol.*`) means the
non-intensional list was emptied by a successful `gen1` derivation. It does not mean
that every preferred parent appeared in a body, nor that tokens were raised to the
configured ceiling.

Second, the grid runner’s **`solved`** label records that ABA Learning completed and
produced a solution artefact. **ASP coverage** (positives covered / negatives rejected
under brave entailment on `bk.sol.asp`) is a separate, post-hoc check of whether that
artefact separates \(\langle E^+,E^-\rangle\). A cell may therefore be runner-`solved`
and still fail to reject negatives.

# Batch A — ECAI (`M12x_ecai2024`)

### ECAI folding control flow

Batch A uses `configs/ecai2024_config.pl`: `learning_mode(brave)`, `folding_mode(nd)`,
`folding_steps(10)`, `folding_selection(any)`, `folding_space(all)`, and
`asm_intro(relto)`. The shared `gen` skeleton above still applies; what follows is how
folding and selection specialise that skeleton on this arm.

**Which rule is folded.** Under `folding_selection(any)`, `gen1` may select any remaining
non-intensional rule (after deleting those already subsumed). There is no preference for
“most general” rote rules.

**How a fold is computed.** Under `folding_mode(nd)`, each fold call is token-bounded.
The token counter starts at \(1\) every run. With \(k\) tokens, non-deterministic folding
may replace body literals by background (or, under `folding_space(all)`, other foldable)
rule heads up to \(k\) times in that call. The first success of the fold procedure is
often a **one-literal** body when \(k=1\): the sample identifier \(A=i\) is replaced by
a single `val` predicate, the trace reports `0: DONE`, and that candidate is passed to
`gen2`. Alternative fold literals for the same rote rule remain as Prolog choice points,
but they are explored only if the accepted path later fails.

**When the token budget rises.** The configured ceiling `folding_steps(10)` is not the
starting budget. `genT` increases tokens by one (and prints
`* Increasing folding tokens to: …`) only if the whole `gen1` search at the current
budget fails. If assumption introduction keeps producing a continuing derivation that
eventually reaches `nothing to fold`, tokens never rise. Multi-literal parent–parent
bodies therefore appear only when earlier one-token (or low-token) repair paths fail hard
enough to force deepening.

**What happens when a fold overgeneralises.** This is the distinctive ECAI behaviour
relative to AAMAS. If `gen2` finds that the folded rule does not entail
\(\langle E^+,E^-\rangle\), the engine does not treat that as a cue to discard the fold
and search for a better body as its primary next step. Under `asm_intro(relto)` it
attempts assumption introduction on **that same** fold: reuse an existing relative
assumption (`gen3`: OK/KO) or mint a new \(\alpha\) and rote-learn its contrary
(`gen6`). Under brave mode, `gen6` does not require entailment before returning to
`gen1`. The effective procedure is therefore **cover-and-repair**: accept a locally
available fold, and if it overgeneralises, push exceptions into assumptions and
contraries rather than retracting the fold in favour of another intension.

**`folding_space(all)`.** Folding is not restricted to the original background-knowledge
block; fold candidates may include other rules admitted into the folding table. In the
M12x tables the first successful one-literal folds are still typically `xi_val_*`
feature predicates, ordered by how `select_rule` enumerates matching heads.

**How to read ECAI traces in this batch.** Lines of the form `begin nd folding` /
`1: folding … with x*_val_*` / `0: DONE` mark a token-bounded fold.
`extended ABA does not entail … looking for assumption` followed by
`generating NEW assumption` or `found: alpha_… OK/KO` mark the repair path. Absence of
`Increasing folding tokens to:` means the derivation completed at the starting budget of
one token. As in the shared skeleton, `nothing to fold` and runner `solved` record
procedural completion; ASP coverage must still be checked separately.

## 1. ECAI × `m12_u1_separator_copy` × \(t=x_2\)

**Cell directory:** `M12x_ecai2024/cells/m12_u1_separator_copy__target-x2/`  
**Runner outcome:** `solved`  
**ASP coverage:** positives `6/6`, negatives `3/3`

### Setup

The graph is a separator \(x_1\to x_2\) with an isolated variable \(x_0\). The mechanism
sets \(x_2\) equal to \(x_1\) on the full nine-row factorial over \((x_0,x_1)\). Under
nonzero-positive labelling the positive examples are rows
\(\{2,3,5,6,8,9\}\) and the negative examples are rows \(\{1,4,7\}\). Background
knowledge contains exact-value predicates for \(x_0\) and \(x_1\); the target column
\(x_2\) is excluded. The ancestors of \(x_2\) are \(\{x_1\}\); the isolated variable
\(x_0\) is a distractor; there are no descendants. The design role of this unit is to
test whether the learner recovers a unary parent rule and avoids citing the isolated
distractor.

### Intended hypothesis \(\mathcal{H}_{x_2}^\star\)

```prolog
x2(A) :- x1_val_1(A).
x2(A) :- x1_val_2(A).
```

These two clauses characterise \(x_2\neq 0\) by the parent \(x_1\) being nonzero. They
must not cite the isolated distractor \(x_0\).

### What happened

This cell uses the ECAI published configuration on unit U1 with learning target \(x_2\).
The learner returned a solved framework with full ASP coverage of the examples. That
framework does not match \(\mathcal{H}_{x_2}^\star\) intensionally. The target rules cite
the isolated distractor \(x_0\) together with assumptions, and the true parent \(x_1\)
appears only in the contrary conditions.

### What the learner did

Learning begins from rote rules that cover each positive example by its sample
identifier:

```prolog
x2(A) :- A=2.
x2(A) :- A=3.
x2(A) :- A=5.
x2(A) :- A=6.
x2(A) :- A=8.
x2(A) :- A=9.
```

Under non-deterministic folding with selection `any` and folding space `all`, the first
successful fold for a representative positive in each \(x_0\)-slice replaces that
identifier by a value predicate of the isolated column \(x_0\). The first fold yields a
body containing only `x0_val_0`; later folds yield only `x0_val_1` and only
`x0_val_2`:

```prolog
x2(A) :- x0_val_0(A).   % from A=2; overgeneralises within the x0=0 slice
x2(A) :- x0_val_1(A).   % from A=5
x2(A) :- x0_val_2(A).   % from A=8
```

Each of those bodies overgeneralises within its slice, because the negative example that
shares the same \(x_0\) value would also be covered. Entailment of the labelled example
set therefore fails, and assumption introduction relative to the failing body adds a
fresh assumption `alpha_1`, `alpha_2`, or `alpha_3`. The remaining positive examples in
the same slice are then deleted as subsumed. The repaired target rules are:

```prolog
x2(A) :- alpha_1(A), x0_val_0(A).
x2(A) :- alpha_2(A), x0_val_1(A).
x2(A) :- alpha_3(A), x0_val_2(A).
```

Contrary learning is driven by the three negative examples, which are exactly the rows
with \(x_1=0\). For each contrary, folding first tries the matching \(x_0\) literal
already used in the corresponding target rule. That attempt is rejected, because the
engine cannot introduce an assumption already tied to that body. Folding then succeeds
with `x1_val_0`:

```prolog
c_alpha_1(A) :- x1_val_0(A).
c_alpha_2(A) :- x1_val_0(A).
c_alpha_3(A) :- x1_val_0(A).
```

The accepted solution therefore has three assumption-mediated target rules keyed by
\(x_0\), and three identical contrary rules that block those assumptions whenever
\(x_1=0\). Body-scope variables of the target rules are \(\{x_0\}\). The parent \(x_1\)
appears only in the framework-scope contrary conditions.

### Match assessment

The learned target rules are not an exact match to \(\mathcal{H}_{x_2}^\star\).

On the complete partition of the table by \(x_0\), an assumption remains undefeated on a
row in that slice if and only if `x1_val_0` fails, which is exactly when
\(x_1\in\{1,2\}\). Taken together, the three rules therefore cover the six positives and
reject the three negatives. In that limited extensional sense the solution agrees with
the nonzero-positive copy semantics of U1.

Intensionally the solution is misaligned with the intended hypothesis. The learner folded
the isolated distractor \(x_0\) before the true parent \(x_1\). It repaired the resulting
overgeneralisation by introducing assumptions. It recovered the true separator only as
contrary conditions on \(x_1\). The intended hypothesis cites \(x_1\) directly in ordinary
target rules and does not mention \(x_0\) at all.

**Short verdict.** The cell is solved and extensionally adequate, but intensionally it
encodes the parent concept through assumptions keyed by the isolated distractor, with
the true parent appearing only in the contraries.

## 2. ECAI × `m12_u2_collider_min` × \(t=x_2\)

**Cell directory:** `M12x_ecai2024/cells/m12_u2_collider_min__target-x2/`  
**Runner outcome:** `solved`  
**ASP coverage:** positives `4/4`, negatives `5/5`

### Setup

Unit U2 is a collider \(x_0\to x_2\leftarrow x_1\) with mechanism \(x_2:=\min(x_0,x_1)\)
on the full nine-row factorial over \((x_0,x_1)\). Under nonzero-positive labelling,
\(x_2\neq 0\) if and only if both parents are nonzero. The positive examples are
therefore rows \(\{5,6,8,9\}\) and the negative examples are rows \(\{1,2,3,4,7\}\).
Background knowledge contains exact-value predicates for both parents; the target
\(x_2\) is excluded. There are no sibling or descendant distractors beyond the two
parents themselves. The design role of this unit is to test recovery of a conjunctive
both-parent rule. The locked reference \(\mathcal{H}_{x_2}^\star\) enumerates that
concept as four ordinary `val` conjunctions, one for each nonzero pair of parent values.

### Intended hypothesis \(\mathcal{H}_{x_2}^\star\)

```prolog
x2(A) :- x0_val_1(A), x1_val_1(A).
x2(A) :- x0_val_1(A), x1_val_2(A).
x2(A) :- x0_val_2(A), x1_val_1(A).
x2(A) :- x0_val_2(A), x1_val_2(A).
```

### What happened

This cell uses the ECAI published configuration on unit U2 with learning target \(x_2\).
The learner returned a solved framework with full ASP coverage. It did not emit the four
locked case clauses. Instead it recovered a compact assumption-mediated representation
of the same semantic idea: \(x_0\) is nonzero in the target bodies, and \(x_1\) is
nonzero through undefeated assumptions whose contraries fire exactly when \(x_1=0\).

### What the learner did

Learning begins from rote rules for the four positives:

```prolog
x2(A) :- A=5.
x2(A) :- A=6.
x2(A) :- A=8.
x2(A) :- A=9.
```

Under non-deterministic folding with selection `any` and folding space `all`, the first
fold for \(A=5\) (where \(x_0=1\)) replaces the sample identifier by `x0_val_1` alone:

```prolog
x2(A) :- x0_val_1(A).
```

That body overgeneralises: it would also cover the negative row \(A=4\), where \(x_0=1\)
but \(x_1=0\). Entailment of the labelled example set therefore fails, and assumption
introduction adds `alpha_1`:

```prolog
x2(A) :- alpha_1(A), x0_val_1(A).
```

The remaining positive in the same \(x_0=1\) slice (\(A=6\)) is then deleted as subsumed.
The same pattern occurs for the \(x_0=2\) slice: fold \(A=8\) to `x0_val_2`, introduce
`alpha_2`, and delete \(A=9\) as subsumed:

```prolog
x2(A) :- alpha_2(A), x0_val_2(A).
```

Contrary learning is driven by the negatives that sit in those same \(x_0\) slices,
namely \(A=4\) and \(A=7\) (both have \(x_1=0\)). Folding each contrary first tries the
matching \(x_0\) literal already used in the corresponding target rule; that attempt is
rejected. Folding then succeeds with `x1_val_0`:

```prolog
c_alpha_1(A) :- x1_val_0(A).
c_alpha_2(A) :- x1_val_0(A).
```

In the ASP solution these assumptions are realised by default-negation rules scoped to
the same \(x_0\)-slices:

```prolog
alpha_1(A) :- not c_alpha_1(A), x0_val_1(A).
alpha_2(A) :- not c_alpha_2(A), x0_val_2(A).
```

Those clauses are what allow each assumption to hold on its slice precisely when the
corresponding contrary fails, that is when \(x_1\neq 0\). Without them, `alpha_1` and
`alpha_2` would never be derived, and the target rules that depend on them would not
cover the positives.

Negatives with \(x_0=0\) (rows \(\{1,2,3\}\)) never enter these target bodies, so they
need no contrary repair. Body-scope variables of the target rules are \(\{x_0\}\). The
second parent \(x_1\) appears in the contrary conditions, and thereby controls whether
the assumptions succeed.

### Match assessment

Relative to the locked case enumeration \(\mathcal{H}_{x_2}^\star\), this is not an
exact syntactic match. The learner does not produce the four ordinary both-parent
conjunctions.

Judged against the semantic success description for U2, however, the learned framework
is a strong and arguably more elegant intensional solution. It characterises nonzero
\(x_2\) under \(\min\) by combining an explicit nonzero condition on one parent in the
target bodies with an assumption-mediated nonzero condition on the other parent. On an
\(x_0\in\{1,2\}\) row, \(x_2\) holds if and only if the assumption is undefeated if and
only if \(x_1\neq 0\). That is exactly “both parents are nonzero,” expressed with two
target rules and the ABA assumption machinery rather than with four case clauses. ASP
coverage is complete for that reason.

So the mismatch with \(\mathcal{H}_{x_2}^\star\) should not be read as a failure to
recover the intended concept. It is a mismatch with one particular syntactic
presentation of that concept. The learned form uses assumptions to represent
nonzeroness compactly.

**Short verdict.** Not an exact match to the locked four-clause \(\mathcal{H}_{x_2}^\star\),
but an elegant assumption-mediated encoding of the same both-parents-nonzero concept,
with full coverage.

## 3. ECAI × `m12_u3_collider_max` × \(t=x_2\)

**Cell directory:** `M12x_ecai2024/cells/m12_u3_collider_max__target-x2/`  
**Runner outcome:** `solved`  
**ASP coverage:** positives `8/8`, negatives `1/1`

### Setup

Unit U3 is the disjunctive counterpart of U2: the same collider \(x_0\to x_2\leftarrow x_1\),
now with mechanism \(x_2:=\max(x_0,x_1)\) on the nine-row factorial. Under
nonzero-positive labelling, \(x_2\neq 0\) if and only if at least one parent is nonzero.
The positive examples are therefore rows \(\{2,3,4,5,6,7,8,9\}\) and the sole negative
is row \(\{1\}\). Background knowledge contains exact-value predicates for both parents;
the target \(x_2\) is excluded. The locked reference \(\mathcal{H}_{x_2}^\star\) is the
four-clause `val` expansion of “at least one parent is nonzero.”

### Intended hypothesis \(\mathcal{H}_{x_2}^\star\)

```prolog
x2(A) :- x0_val_1(A).
x2(A) :- x0_val_2(A).
x2(A) :- x1_val_1(A).
x2(A) :- x1_val_2(A).
```

### What happened

This cell uses the ECAI published configuration on unit U3 with learning target \(x_2\).
After the initial optimum there are eight rote rules, one for each positive.
Non-deterministic folding proceeds by \(x_0\)-slices and yields a mixed solution: pure
unary rules for \(x_0\in\{1,2\}\), and an assumption-mediated rule only on the incomplete
\(x_0=0\) slice. The learner returns a solved framework with full ASP coverage. The
result is not an exact syntactic match to \(\mathcal{H}_{x_2}^\star\), but it is a
compact case analysis that still expresses the intended disjunctive concept.

### What the learner did

Learning begins from rote coverage of the eight positives. The first fold chosen is
\(A=2\) (where \(x_0=0\), \(x_1=1\)), which replaces the identifier by `x0_val_0` alone:

```prolog
x2(A) :- x0_val_0(A).
```

That body would also cover the unique negative \(A=1\) (where \(x_0=0\) and \(x_1=0\)),
so entailment fails and assumption introduction adds `alpha_1`:

```prolog
x2(A) :- alpha_1(A), x0_val_0(A).
```

The other positive in the same slice (\(A=3\)) is then deleted as subsumed. Next, \(A=4\)
folds to `x0_val_1`. Under \(\max\), every row with \(x_0=1\) is already positive, so
this one-literal rule entails \(\langle E^+,E^-\rangle\) immediately and needs no
assumption:

```prolog
x2(A) :- x0_val_1(A).
```

Positives \(A=5\) and \(A=6\) are subsumed. Likewise \(A=7\) folds to a safe unary rule
on the \(x_0=2\) slice:

```prolog
x2(A) :- x0_val_2(A).
```

Positives \(A=8\) and \(A=9\) are subsumed. Contrary learning for the negative \(A=1\)
first tries `x0_val_0` (rejected), then succeeds with `x1_val_0`:

```prolog
c_alpha_1(A) :- x1_val_0(A).
```

In the ASP solution the assumption is realised by

```prolog
alpha_1(A) :- not c_alpha_1(A), x0_val_0(A).
```

# Batch B — AAMAS (`M12x_aamas2025`)

### AAMAS folding control flow

Batch B uses `configs/aamas2025_config.pl`: `learning_mode(brave)`, `folding_mode(greedy)`,
`folding_selection(mgr)`, `folding_space(bk)`, and `asm_intro(relto)`. The shared `gen`
skeleton still applies; what follows is how folding and selection specialise that
skeleton on this arm.

**Which rule is folded.** Under `folding_selection(mgr)`, the engine does not pick an
arbitrary non-intensional rule. After rote learning (and after any later contrary rote
steps), it first computes greedy generalisations of the new non-intensional facts
(`gen: computing greedy foldings`) and stores them in a most-general-first utility table.
`gen1` then selects a rule among those **most general** candidates. The effect in M12x
traces is that each positive’s specialised body is prepared up front, then applied one
rote rule at a time.

**How a fold is computed.** Under `folding_mode(greedy)`, a single fold call walks the
current body and, for each foldable literal, tries every eligible folding rule from the
folding table, accumulating successful head replacements. There is **no token budget**
and no `genT` iterative deepening. On a typical M12x positive \(A=i\), the result is a
**multi-literal** body that cites every background `val` predicate true of that
row—for example

```text
folding result: x3(A) <- [x0_val_0(A),x1_val_1(A),x2_val_0(A)]
```

after successive folds with each matching BK rule. The greedy procedure is committed
(`!`): it does not leave alternative one-literal folds as open choice points in the way
`nd` does.

**`folding_space(bk)`.** Only rules from the original background-knowledge block are
eligible as folding material (rule ids before the learned-rule boundary). Learned target
or contrary rules are not used as fold sources. Combined with greedy accumulation, this
tends to specialise each positive to the full observed feature conjunction available in
BK for that sample.

**What happens when a fold overgeneralises.** The shared `gen2` repair path (assumption
introduction under `relto`, then `gen6` contrary rote learning) remains available. In
practice on the M12x AAMAS cells inspected so far, greedy specialisation is usually
already tight enough that the folded rule entails \(\langle E^+,E^-\rangle\)
immediately. The trace then reports `extended ABA entails <E+,E-> - using folding` and
returns to `gen1` **without** introducing assumptions. When a greedy fold still
overgeneralises, cover-and-repair can still fire—but assumption towers are the exception
on this arm, not the default.

**Contrast with ECAI (Batch A).** ECAI typically proposes a one-literal fold at token
budget \(1\) and, if that overgeneralises, repairs with assumptions. AAMAS typically
proposes a fully specialised BK conjunction in one greedy step and keeps it when it
already separates the examples. The shared failure modes therefore differ in shape:
ECAI’s premature commitment is to an early unary column plus exception structure;
AAMAS’s characteristic residue is **over-specialisation**—retaining extra BK conjuncts
(siblings, ancestors, descendants) beside the literals that would constitute
\(\mathcal{H}_t^\star\).

**How to read AAMAS traces in this batch.** An initial block
`gen: computing greedy foldings` followed by per-sample `folding [A=i] with …` / `DONE`
lines is the precomputation of greedy generalisations. Later `begin greedy folding`
under `gen1` applies that specialisation to the selected rote rule. `using folding`
without intervening `generating NEW assumption` means the fold was accepted
assumption-free. As in the shared skeleton, `nothing to fold` and runner `solved` record
procedural completion; ASP coverage must still be checked separately.
