## Purpose

QI-001 investigates whether the current ABA Learning bridge learns target rules whose body variables coincide with the direct parents of `x2` across three canonical 3-node motifs (chain, fork, collider) and three data representations (binary, 3-valued categorical, continuous binned into 3 uniform bins).

This is not full Causal ABA and not graph recovery. It is a controlled qualitative parent-set recovery investigation using ABA Learning. The current `aba_asp/causal` bridge is treated as a learned-rule / parent-set recovery pipeline over tabular data, not Russo-style Causal ABA.

## Research question

> QI-001 investigates whether the current ABA Learning bridge learns target rules whose body variables coincide with the direct parents of `x2` across three canonical 3-node motifs and three data representations.

Refined operational form:

> For each (motif, data mode) cell, with target `x2` and fixed positive/negative examples, does the learned target rule body for `x2` recover the encoded direct parents of `x2`, and where it does not, what is the failure mode (missing parent, extra ancestor, off-graph, empty delta, no solution)?

## Theoretical motivation

- **ABA foundations:** the learned framework is rules, assumptions, contraries, attacks, and accepted/rejected claims under the learner's semantics.
- **ABA Learning / ABALearn:** QI-001 uses the inherited transformation-rule learner (Rote Learning, Folding, Assumption Introduction) to learn target rules from generated background knowledge and fixed positive/negative examples.
- **Causal ABA / argumentative causal discovery:** QI-001 is causally motivated but does NOT exercise Russo-style `arr`/`noe`/`indep` assumptions, d-separation reasoning, or stable-extensions-as-DAGs. None of that machinery is implemented in the bridge.
- **Current `aba_asp/causal` implementation:** the actual code path is `causal/experiments/run_grid.py` driving `generate_aba_background_knowledge` per target; success is measured as whether the learned `x2` rule body matches `x2`'s encoded parents (`metrics.body_parent_*`).

The qualitative focus matters because aggregate metrics can hide whether a learned body cites true parents versus merely predictive associations. Holding the motif fixed while varying the data representation isolates the effect of the binary/categorical/continuous encoding on what the learner recovers.

## Relation to ABA Learning

- Background knowledge: per-sample feature predicates generated from the non-target columns of each fixture table (`generate_aba_background_knowledge`).
- Positive/negative examples: fixed per fixture (handcrafted), targeting `x2` only. They are NOT regenerated by `pick_target_variable` or a median split, because the handcrafted path returns the fixture's own `pos_examples`/`neg_examples`.
- Target predicate: `x2` (excluded from BK so it cannot trivially appear in its own rule body).
- Learned delta rules / target rules / assumptions / contraries: inspected in a later (run) stage; not produced yet.
- Learner strategy: current defaults (`folding_mode: nd`, `folding_steps: 15`). No greedy-vs-nd comparison in QI-001 (that is QN-001).

## Relation to Causal ABA

- QI-001 may show whether learned ABA rule bodies recover parent-like structure from data generated by a known 3-node motif.
- QI-001 does NOT test full Russo-style Causal ABA: there are no arrow/no-edge/independence assumptions, no d-separation, and no stable-extension-as-DAG correspondence in the code path. The motif names (chain/fork/collider) describe the data-generating structure encoded in the fixtures, not an ABA causal encoding.

## Dataset / data-generating process

### Source

- `handcrafted fixture` (deterministic, fully specified tables).
- Exact generator/function: builders in `causal/experiments/handcrafted_qi001.py`.

### Graph / structure

Three 3-node motifs (0-based node indices; edge `(s, t)` means `xs -> xt`):

```text
chain:    edges ((0,1),(1,2))   -> parents of x2 = {x1}
fork:     edges ((0,1),(0,2))   -> parents of x2 = {x0}
collider: edges ((0,2),(1,2))   -> parents of x2 = {x0, x1}
```

### Variables

| Variable | Meaning | Notes |
|---|---|---|
| `x0` | motif node 0 | non-target; appears in BK |
| `x1` | motif node 1 | non-target; appears in BK |
| `x2` | motif node 2 | target; excluded from BK |

### Sample sizes

- 4-5 rows per fixture (binary/cat: 4-5 rows; continuous: 5 rows). Fully specified, deterministic.

### Seeds

- Single seed `0`. The fixtures are deterministic and ignore the seed; a single seed keeps the grid at exactly 9 cells.

### Noise / stochasticity

The fixtures are deterministic, hand-built tables. Each table encodes the motif dependence with a small amount of off-parent variation so that the non-parent column is not perfectly correlated with `x2`. The precise dependence per fixture is documented in `handcrafted_qi001.py` comments.

## Encoding

Tabular data is converted to ABA predicates by `generate_aba_background_knowledge` with `exclude_cols=[x2]`:

- binary (`categorical` var_type, values exactly `{0,1}`): bare predicates `x0(A) :- A=n.`
- 3-valued categorical (`categorical`, values include `{0,1,2}`): value predicates `x0_val_<v>(A) :- A=n.`
- continuous (`continuous`): binned predicates `x0_bin<k>(A) :- A=n.` with `bins=3`, `bin_strategy=uniform`.

### Target variable(s)

| Target | True parents | Target type | Reason for inclusion |
|---|---:|---|---|
| `x2` (chain) | `{x1}` | single-parent (ancestor `x0` present) | tests parent-over-ancestor recovery |
| `x2` (fork) | `{x0}` | single-parent (common cause) | tests common-cause parent recovery |
| `x2` (collider) | `{x0, x1}` | two-parent collider | tests multi-parent body recovery |

### Positive examples

- binary: `x2 == 1` is positive.
- categorical-3: `x2 == 2` is positive.
- continuous: fixed documented threshold `x2 >= 0.0` is positive (NOT a later median split).

Examples use the repository's 1-based sample-id convention: row index `i` (0-based) maps to atom `x2(i+1)`.

### Negative examples

- The complementary rows for each rule above.

### Background knowledge

- Target excluded from BK: `yes` (`exclude_cols=[x2]`; BK shows `% Skipping excluded variable: x2`).
- Binary features encoded as: bare `x0(A) :- A=n.`
- Non-binary discrete features encoded as: `x0_val_<v>(A) :- A=n.`
- Continuous features encoded as: `x0_bin<k>(A) :- A=n.` (`bins=3`, `bin_strategy=uniform`).
