# Batch A — ECAI / ASP-ABAlearnB (`M12_ecai2024`)

## 1. ECAI × `m12_sep`

### Data-generating process and intended graph

- **G:** `x1 → x2`; `x0` isolated (no edge involving `x0`).
- **Mechanism:** complete factorial over `(x0,x1) ∈ {0,1,2}²` (9 rows); `x2 := x1`.
- **Label:** positive iff `x2 = 2` iff `x1 = 2` → E+ = `{x2(3), x2(6), x2(9)}` (rows with `x1=2`).
- **Design role:** separator anchor — a unique zero-error parent (`x1`); isolated `x0` is associated with neither label nor mechanism.

### Intended learned rule

```prolog
x2(A) :- x1_val_2(A).
```

No assumptions required.

### What the learner did (logical trace reading)

Rote seeds cover each positive by id (`x2(A) ← [A=3]`, `[A=6]`, `[A=9]`). Under
`nd`/`any`/`all`, the first folding step for `A=3` replaces the id literal by
`x0_val_0(A)` (the value of the *isolated* column on that row), yielding
`x2(A) ← [x0_val_0(A)]`. That overgeneralises: every row with `x0=0` would be
covered, including negatives. Entailment of `<E+,E−>` therefore fails, and
`asm_intro(relto)` introduces `alpha_1(A)`, producing

```prolog
x2(A) :- alpha_1(A), x0_val_0(A).
```

The same pattern repeats for positives 6 and 9 with `x0_val_1` / `x0_val_2` and
`alpha_2` / `alpha_3`. Negatives under each `x0`-slice then become contrary-learning
tasks: fold `c_alpha_i(A) ← [A=id]` first tries the same `x0` literal (rejected —
cannot introduce an assumption already tied to that body), then succeeds with
`x1_val_0` / `x1_val_1` (the non-positive values of the true parent).

**Learned δ (target + framework):**

```prolog
x2(A) :- alpha_1(A), x0_val_0(A).
x2(A) :- alpha_2(A), x0_val_1(A).
x2(A) :- alpha_3(A), x0_val_2(A).
c_alpha_1(A) :- x1_val_0(A).
c_alpha_1(A) :- x1_val_1(A).
% (same contrary pattern for alpha_2, alpha_3)
assumption(alpha_i(A)).  contrary(alpha_i(A), c_alpha_i(A)) :- assumption(alpha_i(A)).
```

### Match assessment

**Not an exact match.** Under value exclusivity, undefeated `alpha_i` on an `x0=i`
row holds precisely when `x1 ∉ {0,1}`, i.e. when `x1=2`. The three rules together are
therefore extensionally equivalent (on a complete `x0` partition) to `x1_val_2`.
Intensionally, however, the learner:

1. folded the *wrong* column first (`x0` before `x1`);
2. repaired overgeneralisation by assumption introduction;
3. recovered the true separator only as *contrary* conditions.

Outcome class: **misaligned assumption structure** (extensionally adequate, intensionally
not the locked singleton). ASP side-car (2026-07-13): `pos_covered=3/3`,
`neg_rejected=6/6`.

## 2. ECAI × `m12_conj`

### Data-generating process and intended graph

- **G:** collider `x0 → x2 ← x1`.
- **Mechanism:** `x2 := min(x0,x1)`; positive iff `x0=2 ∧ x1=2` (single row 9).
- **Design role:** no one-literal value predicate separates; the locked target is the
  two-literal conjunction.

### Intended learned rule

```prolog
x2(A) :- x0_val_2(A), x1_val_2(A).
```

### What the learner did

Single positive `A=9` folds first to `x0_val_2(A)` alone. That covers negatives 7 and 8
(`x0=2`, `x1∈{0,1}`), so entailment fails → `alpha_1` is introduced:

```prolog
x2(A) :- alpha_1(A), x0_val_2(A).
```

Contrary learning on those negatives folds `c_alpha_1` to `x1_val_0` and `x1_val_1`
(again after rejecting a self-referential `x0_val_2` fold).

### Match assessment

**Not exact.** Extensional reading: `x0=2` and undefeated `alpha_1` iff not (`x1=0` or
`x1=1`) iff `x1=2` → same coverage as the intended conjunction on the factorial table.
Intensionally this is assumption/contrary encoding of a conjunction, not the locked
two-literal rule. Body-scope reports only `{x0}`; `x1` appears only in framework-scope
contraries.

Outcome class: **misaligned assumption structure**.

## 3. ECAI × `m12_disj`

### Data-generating process and intended graph

- **G:** same collider as conj.
- **Mechanism:** `x2 := max(x0,x1)`; positive iff `x0=2 ∨ x1=2` (five positives).
- **Design role:** twin of conj; intended compact OR as a *two-rule set*.

### Intended learned rules

```prolog
x2(A) :- x0_val_2(A).
x2(A) :- x1_val_2(A).
```

### What the learner did

Positives are covered by case-splitting on `x0`:

- `A=3` (`x0=0,x1=2`): fold to `x0_val_0` → overgeneral → `alpha_1`; contraries
  `x1_val_0`/`x1_val_1` (so this branch ≈ `x0=0 ∧ x1=2`).
- `A=6` (`x0=1,x1=2`): same pattern with `alpha_2` (≈ `x0=1 ∧ x1=2`).
- `A=7` (`x0=2,x1=0`): fold to `x0_val_2` **succeeds without assumption** — because
  every `x0=2` row is positive under `max`. Remaining positives 8 and 9 are then already
  covered by that rule.

**Learned target rules:**

```prolog
x2(A) :- alpha_1(A), x0_val_0(A).
x2(A) :- alpha_2(A), x0_val_1(A).
x2(A) :- x0_val_2(A).
```

### Match assessment

**Not exact.** Extensional union on the factorial table is
`(x0=0 ∧ x1=2) ∨ (x0=1 ∧ x1=2) ∨ (x0=2)`, which equals `(x0=2) ∨ (x1=2)` — the intended
OR. The learner never emits the clean two-rule form; it emits a case analysis on `x0`
with assumption repair on the incomplete slices. Notably it *does* recover the pure
`x0_val_2` disjunct when that literal alone is safe, but never invents a standalone
`x1_val_2` rule.

Outcome class: **misaligned assumption structure** / failure to emit compact OR.

## 4. ECAI × `m12_fork`

### Data-generating process and intended graph

- **G:** fork `x0 → x1`, `x0 → x2`.
- **Mechanism (deterministic):** rows `(x0,x1,x2) = (0,0,0), (1,2,0), (2,0,2)`;
  `x1 := 2` iff `x0=1` else `0`; `x2 := 2` iff `x0=2` else `0`.
- **E+:** `{x2(3)}` only. Sibling `x1` is associated with `x2` through the shared cause
  but is **not** a zero-error separator.

### Intended learned rule

```prolog
x2(A) :- x0_val_2(A).
```

### What the learner did

Single positive folds in one `nd` step to `x0_val_2(A)`. Entailment holds immediately
(no negative shares `x0=2`). No assumption introduced.

**Learned δ:**

```prolog
x2(A) :- x0_val_2(A).
```

### Match assessment

**Exact match.** This is the one ECAI cell where the first successful fold is already the
mechanism parent and is safe without repair. The sibling `x1_val_0` (true on the positive
row) was not selected as the sole fold — under this run’s nondeterministic choices the
parent won.

Outcome class: **exact expected match**.

## 5. ECAI × `m12_chain`

### Data-generating process and intended graph

- **G:** `x0 → x1 → x2`.
- **Mechanism:** for each `x0∈{0,1,2}` include `x1:=x0` and `x1:=(x0+1) mod 3`;
  `x2:=x1` (6 rows). Parent `x1` is the unique zero-error separator; ancestor `x0` is
  imperfectly associated (`P(pos|x0)` = 0, 1/2, 1/2).

### Intended learned rule

```prolog
x2(A) :- x1_val_2(A).
```

### What the learner did

Positives `A=4` (`x0=1,x1=2`) and `A=5` (`x0=2,x1=2`) fold first to **ancestor**
literals `x0_val_1` and `x0_val_2`. Each overgeneralises within its `x0`-slice →
assumptions `alpha_1`, `alpha_2`. Contrary learning then folds the *exceptions* to
`x1_val_1` (defeats the false positive at row 3) and `x1_val_0` (defeats row 6):

```prolog
x2(A) :- alpha_1(A), x0_val_1(A).
x2(A) :- alpha_2(A), x0_val_2(A).
c_alpha_1(A) :- x1_val_1(A).
c_alpha_2(A) :- x1_val_0(A).
```

### Match assessment

**Not exact.** On the *observed* six rows this is extensionally adequate (positives
survive; the two false-positive candidates in those slices are defeated). It is the
textbook **ancestor citation** failure mode: the body cites `x0`, and the true parent
appears only as contrary conditions. On a fuller `(x0,x1)` table the same framework would
not coincide with `x1_val_2` (e.g. `x0=1,x1=0` would keep `alpha_1` undefeated).

Outcome class: **ancestor citation**.

## Method conclusion — ECAI (cells 1–5)

Across the five ECAI cells a single procedural motif dominates. Under
`nd`/`any`/`all`, folding often commits early to a **single value literal of a
non-minimal or wrong column** (`x0` on sep/chain; one parent only on conj). When that
literal is unsafe, `asm_intro(relto)` + contrary learning reconstruct an
extensionally workable theory by *defeating* the overgeneral cases — frequently using
the true mechanism variable only in contrary heads. The result is systematically
**assumption-heavy**, body-scope-poor relative to the locked rules, and rarely an exact
intensional match even when coverage on the sample is perfect.

The striking exception is `m12_fork`, where the parent literal is immediately safe and
exact. `m12_disj` shows a mixed pattern: a pure parent disjunct is emitted when safe
(`x0_val_2`), while the other half of the OR is reconstructed via assumption case-split
rather than as `x1_val_2`. ECAI therefore tends to prefer **local repair of bad folds**
over **search for the most compact mechanism-aligned rule set**.

# Batch B — AAMAS / Greedy ABA Learning (`M12_aamas2025`)

## 6. AAMAS × `m12_sep`

### DGP / graph / intended rule

Same as §1: intended `x2(A) :- x1_val_2(A).`

### What the learner did

Greedy/`mgr` folds each positive to the conjunction of both column values on that row.
Entailment holds **without** assumptions:

```prolog
x2(A) :- x0_val_0(A), x1_val_2(A).
x2(A) :- x0_val_1(A), x1_val_2(A).
x2(A) :- x0_val_2(A), x1_val_2(A).
```

No further generalization merges these into the singleton `x1_val_2`.

### Match assessment

**Not exact.** Logically, under mutual exclusivity and exhaustiveness of `{x0_val_0,
x0_val_1, x0_val_2}`, the three rules are equivalent to the intended singleton. The
learner stops at a **case-split residue / parent-superset**: the isolated column remains
in every body even though it is causally irrelevant and logically eliminable.

Outcome class: **parent-superset** (failure to generalize across positive cases).

### DGP / graph / intended rule

Same as §2: intended two-literal conjunction.

### What the learner did

Single positive folds directly to

```prolog
x2(A) :- x0_val_2(A), x1_val_2(A).
```

Entailment holds; no assumption.

### Match assessment

**Exact match.** With one positive and a conjunctive mechanism, greedy’s full-feature

## 8. AAMAS × `m12_disj`

### DGP / graph / intended rules

Same as §3: intended two-rule OR.

### What the learner did

Five positives → five specialized conjunctions (no assumptions):

```prolog
x2(A) :- x0_val_0(A), x1_val_2(A).
x2(A) :- x0_val_1(A), x1_val_2(A).
x2(A) :- x0_val_2(A), x1_val_0(A).
x2(A) :- x0_val_2(A), x1_val_1(A).
x2(A) :- x0_val_2(A), x1_val_2(A).
```

### Match assessment

**Not exact.** The learner emits a five-cell DNF enumeration and never lifts the cells
into the two compact disjuncts. Extensional coverage on the table is fine; intensional
mechanism alignment (OR-as-two-rules) fails.

Outcome class: **positive-cell enumeration (DNF)**.

## Method conclusion — AAMAS (cells 6–10)

AAMAS is **assumption-free** on these coherent fixtures: greedy folds that already cover
without harming E− are accepted bare. This differs from ECAI’s observed
contrary-repair path, although both scoped arms have
`post_folding_test_entailment(true)`.

What remains is a different failure family:

- **Over-specialization / failure to generalize** (sep: three rules instead of one;
  chain/fork: keep correlated distractors).
- **Failure of disjunctive compression** (disj: five-cell DNF vs two-rule OR).
- **One exact success** when specialization *coincides* with the mechanism (conj).

Relative to the locked “mechanism-aligned rule” criterion, AAMAS is often the most
readable (pure target rules, no assumptions) but still rarely exact. Exactness occurs
when the intended rule *is* the greedy specialization of the positive set — not when
further abstraction (drop a column; merge into OR) is required.

# Overarching conclusion — failure modes

Why the locked intended rules were not learned (8/10 cells), organised as recurring
modes. Modes are descriptive of *this* grid’s evidence; attribution depth (paradigm vs
published variant vs encoding) is deferred to M1.3.

### FM1 — Wrong-column-first fold + assumption/contrary repair (ECAI-dominant)

**Seen in:** ECAI sep, conj, chain; partially disj.  
**Mechanism:** `nd`/`any` selects a fold that overgeneralises; `asm_intro(relto)` patches
with assumptions; true separators often land in **contrary** rules.  
**Why intended fails:** locked targets are assumption-free singletons/conjunctions/ORs;
learned theories are different intensional objects even when sample-extensionally
similar.

### FM2 — N/A in the current two-arm scope

No ECAI or AAMAS cell instantiates the removed-arm-only scaffolding pattern previously
assigned this identifier. FM2 is retained as N/A so existing FM numbering remains stable.

### FM3 — Positive-cell DNF enumeration / failure of disjunctive compression

**Seen in:** AAMAS disj; ECAI disj is a hybrid case-split.  
**Mechanism:** each positive example becomes its own conjunctive rule; learning stops
when E+ is covered.  
**Why intended fails:** the locked target is a *two-rule OR*, not a five-clause DNF of
cells. Completeness+consistency of the compact OR is Stage-0 verified, so the
hypothesis exists in the language — the search/strategy does not emit it.

### FM4 — Failure to drop redundant co-occurring features (parent-superset)

**Seen in:** AAMAS sep (redundant `x0`); AAMAS chain (redundant `x0`);
AAMAS fork (redundant `x1`).  
**Mechanism:** greedy specialization keeps all literals true of the covered positives
that remain consistent with E−; no later compression deletes them.  
**Why intended fails:** locked rules are minimal separators; learned rules are safe
supersets.

### FM5 — Sibling citation (fork-designed)

**Seen in:** AAMAS fork; **not** ECAI fork (exact).  
**Mechanism:** on the sole positive, sibling value `x1_val_0` co-occurs with
`x0_val_2`; greedy keeps both.  
**Why intended fails:** sibling is not a parent in G and is not a zero-error separator.

### FM6 — Ancestor citation (chain-designed)

**Seen in:** ECAI chain (ancestor in target body, parent in contraries); AAMAS chain
(ancestor ∧ parent in target bodies).  
**Mechanism:** association between ancestor and label, plus fold preference / greedy
specialization, retains `x0`.  
**Why intended fails:** locked rule cites only the direct parent `x1`.

### FM7 — Extensional adequacy ≠ intensional match (cross-cutting)

ASP coverage (2026-07-13 side-car) is **full on all 10 cells**: every positive is
bravely entailed and every negative is not (`pos_covered` / `neg_rejected` complete
fractions in `M12_summary.md`). Several non-exact cells are therefore
sample-extensionally adequate under the learned ASP encoding (especially ECAI’s
assumption encodings and AAMAS’s case-splits) while still failing the locked
intensional target. The M1.2 success criterion remains **pre-specified intended
output**, not mere coverage. Treating ASP coverage as success would hide FM1 and
FM3–FM6.

### What did work (boundary conditions for exactness)

| Cell | Why exactness was possible here |
|---|---|
| ECAI × fork | One positive; first safe one-literal fold = parent; no distractor forced. |
| AAMAS × conj | One positive; intended rule *is* the full feature conjunction on that row. |

Exactness in this grid is therefore **fragile coincidence between strategy and
fixture shape**, not a general guarantee that published configs recover mechanism-aligned
rules on divergence-designed categorical data.

  ASP coverage); `body_equals_expected_up_to_perm`; `extensional_eq_on_sample` vs
  `extensional_eq_on_full_factorial`.
