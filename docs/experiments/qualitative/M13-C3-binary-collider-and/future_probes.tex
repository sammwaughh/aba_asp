\subsection*{Motivation (verified)}
ECAI brave targets \(a\) and \(b\) \texttt{solved} with assumption-rich deltas
(11 delta rules, 3 assumptions).
Rows~9 \((1,0,0)\) (\(E^+\)) and~26 \((0,0,0)\) (\(E^-\)) share BK literals
\texttt{b\_val\_0}, \texttt{c\_val\_0}.
Brave delta includes the \(\alpha_2/\alpha_3\) nest on the both-0 cell
(\texttt{delta.aba}): a per-row assumption choice gadget can Hold at~9 and
Reject at~26 across different stable models.
Runner \texttt{solved} \(\neq\) root-mechanism recovery.
In \texttt{asp\_engine.pl}, brave \texttt{entails/5} is existential under joint
\(E^\pm\) constraints; cautious requires \(E^+\) in cautious consequences.
The brave delta is predicted to fail cautious entailment (e.g.\ \(a(9)\) not
true in every answer set).

\subsection*{Infrastructure prerequisite (required; not yet done)}
Target-wise currently hard-requires brave
(\texttt{causal/targetwise/config.py}, \texttt{\_read\_learning\_mode};
README). Learning mode is read from the consulted \texttt{.pl}, not a free YAML
field. H4 is \emph{not} a one-line YAML change.

Two-stage plan:
\begin{enumerate}
  \item \textbf{Infra:} new Prolog options file (do not edit
    \texttt{ecai2024\_config.pl} in place) with

    \texttt{n30\_seed42} for roots \(a,b\) (optional \(c\)).
\end{enumerate}
