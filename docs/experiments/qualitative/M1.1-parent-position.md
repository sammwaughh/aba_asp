## Purpose

m1.1 is a metamorphic validity control on the QL2 (QI-002) parent-recovery
proxy. It tests whether the existing target-wise ABA Learning behaviour follows
the variable that occupies the direct-parent role, rather than a fixed variable
identity (e.g. `x0`) or a fixed learner-visible representation position. This
record covers fixture generation, Stage-0 validation, the Phase A eight-cell
nd grid (Stages 1–3), Phase B mechanistic investigation and ablations (Stages 4–6).
investigation, NOT Russo-style Causal ABA.

**What this test is:** parent-rule recovery on minimal complete factorial tables
where one predictor is a **deterministic direct cause** of `x2` (`x2 := parent`)
and the other predictor is **statistically isolated** (no link to `x2` in the
table). The experiment then applies identity (`pi`) and representation-order
(`sigma`) transformations and checks whether the learnt rule tracks the direct
cause.

**What this test is not:** chain discovery, faithful chain SCM sampling, or
observational recovery of a correlated ancestor. Chain-style edge annotations in
the fixtures label which variable is parent vs non-parent for the `pi` swap;
they do **not** define the tabular DGP. A faithful correlated-ancestor chain
remains QI-003/QI-004 territory.

**Extended scope (June 2026, supervisor guidance):** m1.1 expanded from verdict table to
mechanistic account and ablations; supervisor requirements **addressed**; status **`analysed`**.
M1.2 (greedy vs nd) is the next comparator experiment, not required to explain cat3 σ failure.

## Research question

> Under complete, noiseless QL2-style target-mechanism tables, when the
> direct-parent and non-parent roles are exchanged between `x0` and `x1`, and the
> learner-visible predictor order is independently reversed, does the learnt
> `x2` rule follow the variable occupying the direct-parent role?

Stage-0 established that the eight fixtures are correctly constructed and that
the requested predictor order is exposed in the learner-visible BK. Phase A (Stages
1–3) supplied metamorphic verdicts and a provisional triggered trace for cat3 σ.
Phase B (Stages 4–6) and Stage 7 (greedy comparator) completed the mechanistic account and closure.

## Theoretical motivation

- **ABA foundations:** assumptions, contraries, attacks, extensions — unchanged.
- **ABA Learning / ABALearn:** transformation-rule learning from BK and E+/E-;
  the fixed strategy is QI-002-style non-deterministic folding.
- **Causal ABA / argumentative causal discovery:** NOT exercised here (no
  arr/noe/indep, no d-separation, no stable-extension-as-DAG).
- **Current `aba_asp/causal` implementation:** tabular data → feature-predicate
  BK → per-target learning → compare learnt body against the known parent.

The QL2 categorical chain returned a rule referring to `x0` where the expected
direct parent was `x1`. m1.1 separates three explanations: direct-parent-role
tracking, fixed variable identity, and fixed representation position, by crossing
parent identity with learner-visible predictor order.

## Relation to Causal ABA

NOT test full Russo-style Causal ABA, causal discovery, or whole-graph recovery.

## Representation-order finding (provisional — Phase A only)

The learner-visible predictor order is the **DataFrame column order**.
`generate_aba_background_knowledge` serialises BK by iterating `for col in
df.columns` and skipping the excluded target; there is no sort or canonicalisation
in the bridge (`causal/argcausaldisco_integration.py`) or in
`utils/data_utils.py`, and `execute_cell_stage1` preserves order via
`fx.df.copy()`. So reversing predictor order is implemented as a fixture column
reorder (`x2` kept last), and this propagates verbatim into `bk.aba`.

**Stage 3 observation (historical):** on cat3 σ-pairs, nd folding’s first literal
tried follows BK predicate-block order, which **coincides with** entailment vs
assumption branches when A/B differ. **Superseded by Stage 4–6** (mechanistic account + ablations).

## Dataset / data-generating process

### Source

- Handcrafted fixtures; canonical cell A built in `handcrafted_m11.py`, with
  cells B/C/D derived from A via `sigma` and `pi`.

### Data-level DGP (what the table encodes)

Every cell uses the same **tabular mechanism**:

- enumerate every `(x0, x1)` assignment once (binary: 4 rows; cat3: 9 rows);
- set **`x2 := parent`** deterministically (noiseless copy of the designated
  direct cause);
- the **non-parent** varies independently in the factorial and is therefore
  **marginally independent** of both the parent and `x2`.

At the data level each cell is therefore **one isolated predictor plus a
connected parent–target pair**, not a sampled chain:

| Cell | Parent | Isolated (non-parent) | Data-level graph | Mechanism |
|------|--------|----------------------|------------------|-----------|
| A, B | `x1` | `x0` | `x0` ; `x1 → x2` | `x2 := x1` |
| C, D | `x0` | `x1` | `x1` ; `x0 → x2` | `x2 := x0` |

(A semicolon means no causal link in the table; `→` is the deterministic copy
relation enforced row-by-row.)

The true parent is the **unique zero-error one-literal separator**; the isolated
variable cannot win by spurious correlation.

### Role labels (not the tabular DGP)

Fixtures also carry **chain-style role annotations** used only to define which
variable is “parent” vs “non-parent” under `pi`:

```text
Cells A/B (parent x1):  role label x0 -- ancestor/non-parent ; x1 -- parent of x2
Cells C/D (parent x0):  role label x1 -- ancestor/non-parent ; x0 -- parent of x2
```

These labels do **not** imply an edge from the isolated variable to the parent
in the generated table. They are inherited naming from the QI-002 chain motif
and support the parent-position swap; they must not be read as “we tested chain
observational data.”

### Transformations (`sigma`, `pi`)

Two independent knobs (see transformation orbit below):

| Transform | Changes | Does not change |
|-----------|---------|-----------------|
| **`sigma`** | Learner-visible **predictor column order** (and therefore BK predicate-block order) | Variable names, row values, which variable is parent, E+/E− |
| **`pi`** | **Identity swap** `x0 ↔ x1` (column names and value columns together) | `x2` values, sample ids, the isolated-vs-parent table structure |

- **A → B, D → C:** `sigma` only (parent unchanged; order flips).
- **A → D, B → C:** `pi` only (parent swaps; order unchanged relative to each pair).

### Binary example (cell A)

| x0 | x1 | x2 |
|----|----|-----|
| 0 | 0 | 0 |
| 0 | 1 | 1 |
| 1 | 0 | 0 |
| 1 | 1 | 1 |

`x2` always equals `x1`; `x0` varies independently → `x0 ⊥ x2`. Expected learnt
rule: `x2(A) <- x1(A)`. Cell B has the same joint assignments with columns
`[x1, x0]`; cells C/D swap parent/isolated roles under `pi`.

## Design inheritance audit (vs QL2 / QI-002)

The fixtures inherit structure from QI-002. The audit below records which
inherited choices are principled and which were corrected for m1.1. Reducing the
per-assignment repeat to 1 (minimal complete factorial; 4 binary / 9 cat3 rows)
does not change separator logic or `pi`/`sigma` validity. Code evidence: the
learner imposes no `|E+| >= 2` requirement (`rote_learning.pl` has only a
`sort/2`, no example-count guard), and QI-001's chain-binary fixture already ran
a 4-row full factorial successfully (register: QI-001 "9/9 solved"). Even at one
row per assignment, the x1-parent binary cell has `|E+| = 2` and cat3 has
`|E+| = 3`.

| Design choice | QI-002 / QL2 | m1.1 current | Principled? | Recommendation |
|---|---|---|---|---|
| Full factorial over `(x0,x1)` | yes | yes | yes | keep |
| `x2` per-assignment repeat | yes ("avoids single-row flukes", weak) | corrected to `_REPEATS = 1` | no (no separator / `pi`/`sigma` effect; no engine requirement) | removed (minimal factorial) |
| Single orientation vs `pi`/`sigma` cells | single canonical orientation per motif | adds `pi`/`sigma` cells (A/B/C/D) | yes | keep (good inheritance) |
| Decorrelated `x0` vs faithful chain | decorrelated factorial (not a faithful chain SCM) | same | yes for the unique-separator question | keep; document the boundary (faithful chain = QI-003/QI-004) |
| Binary positive-only BK | bare positive-case predicate `x0(A)` for `{0,1}` | same via shared BK writer | yes (existing encoding contract) | keep unchanged |

### Transformation orbit (per encoding)

```text
A --sigma--> B
|             |
pi            pi
v             v
D --sigma--> C
```

- `sigma`: reverse learner-visible predictor order; values/examples/ids/roles/target unchanged.
- `pi`: exchange `x0`<->`x1` (names and values together); relabel edges via 0<->1; fix `x2` and sample ids.
- `B = sigma(A)`, `D = pi(A)`, `C = sigma(D) = pi(B)`.

### Where the traces diverge (line 35)

### Why `select_rule` picks different BK rules (same algorithm, permuted order)

Nd folding calls `select_rule/3` (`folding.pl`), which:

1. Looks up `fwt` entry for `ftw_term_key(A=3)` → `=/2`.
2. Walks rule IDs **in list order** (BK read order).
3. Skips IDs whose body literal does not subsume `A=3` (IDs 1–2 fail).
4. **First success is always ID 3** — the third line of that cell’s `bk.aba`.

At row 3 (`x0=0, x1=2`), **both** `x0_val_0(A):-A=3` and `x1_val_2(A):-A=3` are valid
fold partners. σ swaps which block’s matching rule sits at ID 3 vs ID 12. The engine has
no parent-role signal — only **first successful ID in the `=/2` bucket**.

**Why entailment fails in A but passes in B (data semantics):**

| Predicate | True on row ids | Negatives covered? |
|-----------|-----------------|-------------------|
| `x0_val_0` | 1, 2, **3** | **yes** (1, 2 ∈ E−) |
| `x0_val_1` | 4, 5, **6** | **yes** (4, 5) |
| `x0_val_2` | 7, 8, **9** | **yes** (7, 8) |
| `x1_val_2` | **3, 6, 9** only | **no** |

- **B:** `x2(A):-x1_val_2(A)` covers E+ exactly → cautious entailment OK → other rote rules subsumed → **stop** (~54 trace lines).
- **A:** `x2(A):-x0_val_0(A)` also derives `x2(1), x2(2)` → entailment FAIL → assumption path.

### Why A’s trace is long and cannot recover B’s singleton rule

**Trace length:** A repeats for each positive (3, 6, 9): failed fold → new `alpha_i` →
`gen6` contrary rote (2 per alpha) → then six contrary-rule folds (lines 78–161) where
`x0` fold fails and nd **backtracks** to `x1` fold. B completes after one successful fold.

**Why A never produces `x2(A) :- x1_val_2(A)`:**

1. **No retry of parent fold on failed entailment:** when `x2 <- x0_val_0` fails
   `gen2`, there is no existing assumption for `relto` on the first target fold, so the
   engine commits to **NEW assumption** (`alpha_1`) instead of backtracking `select_rule`
   to try `x1_val_2` at ID 12.
2. **Rote rule consumed:** `gen1` removes `x2(A)<-[A=3]` before folding; after the
   assumption path it is replaced by `x2(A):-alpha_1(A), x0_val_0(A)` — not available
   for a second fold with `x1_val_2`.
3. **Same for rows 6 and 9:** three separate `alpha_i` + `x0_val_*` target rules.
4. **`gen1` only folds non-intensional rules** (body contains ground equality `X=C`).
   Assumption-augmented `x2` rules have no equalities → never re-selected.
5. **Later `x1_val_*` folds apply to `c_alpha_*` heads only** (exception/contrary repair),
   not to `x2`. Both cells satisfy E+/E− at termination; A’s solution is a **defeasible
   patchwork**, not the minimal intensional parent rule.

**Learnt outputs:**

- B: `x2(A) :- x1_val_2(A).` (19 rules total)
- A: three `x2(A):-alpha_i(A), x0_val_i(A).` + six folded `c_alpha_i` rules on `x1_val_*`
  (35 rules in sol file; 27 in ABA size count)

### ABA Learning theory (bounded)

- **Folding** (Proietti–Toni): generalise rote equalities using BK predicates — path to
  intensional solutions.
- **Entailment** (cautious): filter folds that cover E+ but also E−.
- **Assumption introduction**: fallback when a fold is syntactically valid but semantically
  incompatible with E+/E− (undercutting repair).

B takes the folding path once. A takes the assumption path three times; parent features
appear only in **contrary** rules, not as a unified `x2` rule.

### Testable hypothesis (for Stage 6 ablations)

> Under nd + cautious + relto, when multiple BK rules subsume the same rote equality literal,
> **the first successful `select_rule` candidate is determined solely by BK rule-ID order**
> (hence σ block order); entailment then decides accept vs assumption commitment; **failed
> entailment on the first target fold does not backtrack to later BK candidates** for that
> rote rule.

**Predictions:** placing the parent block first in BK (σ reversal) should recover B-like
singleton behaviour without changing E+/E− or BK content; forcing parent-first order on A’s
table should match B’s trace shape. D vs C should mirror A vs B under the other σ-pair.
